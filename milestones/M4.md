# M4 — Streaming itinerary engine

## Role

Act as Project Manager/Supervisor. Delegate the SSE transport and agent-stream integration as separate tasks, but define the event contract centrally before implementation.

## Objective

Expose a robust Server-Sent Events endpoint that streams agent progress and itinerary content to a client incrementally.

## Transport

Implement a versioned endpoint such as:

`POST /api/v1/trips/stream`

Use SSE-compatible response headers and a documented request/response lifecycle. Because browser `EventSource` does not support POST bodies natively, use `fetch()` with a streaming response reader on the frontend.

## Event contract

Define and document typed events, for example:

- `trip.started`
- `trip.status`
- `tool.started`
- `tool.completed`
- `tool.failed`
- `itinerary.delta`
- `itinerary.section`
- `trip.completed`
- `trip.error`

Each event should include:
- `type`
- `tripId`
- `sequence`
- `timestamp`
- typed `data`

Do not stream raw provider payloads, credentials, hidden reasoning or internal chain-of-thought. Progress events should describe observable actions (for example "Searching flights") rather than expose private model reasoning.

## Behavior

- Stream status updates as work progresses.
- Stream user-visible itinerary text/sections as they become available.
- Keep structured itinerary data separate from prose deltas.
- Ensure the final completion event includes a validated structured result or a clear partial-result status.
- Support client disconnect and AbortSignal cancellation.
- Handle backpressure, heartbeat/keep-alive and clean connection teardown.
- Avoid duplicate terminal events.
- Send safe structured error events if failure occurs after streaming begins.
- Set maximum stream duration and resource limits.
- Add request correlation and sequence numbers.

## Tests

- Test event serialization and ordering.
- Test partial output, successful completion, tool failure and model failure.
- Test client disconnect and cancellation.
- Test that no hidden reasoning, credentials or unfiltered raw API payloads are streamed.
- Test malformed requests and rate limiting.
- Use a mocked agent/provider stack in CI.

## Delegation

- Backend agent: SSE route and lifecycle.
- AI agent: adapt agent loop to emit typed progress/content events.
- QA agent: event ordering, disconnect, cancellation and redaction tests.
- Supervisor: event contract ownership, integration and end-to-end tests.

## Acceptance criteria

- [ ] SSE endpoint streams multiple typed events.
- [ ] Frontend-compatible POST/fetch streaming approach is documented.
- [ ] Itinerary content appears incrementally.
- [ ] Tool status is visible without exposing hidden reasoning.
- [ ] Cancellation and disconnect work.
- [ ] Errors are structured and safe.
- [ ] Event order and terminal behavior are tested.
- [ ] Human approves before M5.
