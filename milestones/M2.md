# M2 — External provider integrations

## Role

Act as Project Manager/Supervisor. Read the approved architecture and M0 provider research. Delegate one provider adapter per isolated worktree. Keep provider credentials on the backend only.

## Objective

Implement independently testable adapters for flight search, weather, geocoding, places and route calculations. Normalize results into stable internal domain types.

## Provider requirements

### Flights — Amadeus
- Implement OAuth token acquisition and safe token caching/refresh.
- Implement Flight Offers Search using the supported Amadeus endpoint and documented required fields.
- Support origin/destination IATA codes, departure date, optional return date, passenger count, currency, non-stop preference and result limit as supported.
- Validate input before sending requests.
- Normalize airline, flight segments, departure/arrival timestamps, duration, stops, baggage information when supplied, price, currency, source and retrieval timestamp.
- Handle expired tokens, rate limits, timeouts, provider errors and empty results.
- Distinguish test and production base URLs through configuration.
- Mark test-environment results as test data. Do not label them live production availability.
- Do not implement booking or payment.

### Weather — Open-Meteo
- Implement geocoding and forecast lookup by coordinates.
- Retrieve only the variables needed for itinerary planning (daily highs/lows, precipitation probability/amount, weather code and relevant hourly data).
- Make forecast horizon explicit. If the requested trip is outside the available forecast horizon, return a clear `forecast_unavailable_for_dates` result rather than inventing weather.
- Include timezone, units, provider attribution, retrieval timestamp and forecast dates.
- Respect the free endpoint's non-commercial policy and usage limits.

### Maps and places — Google Maps Platform
- Implement Places API (New) text search for attractions and restaurants.
- Implement Place Details only for fields actually required; use field masks to minimize cost.
- Implement Geocoding where needed.
- Implement Routes API for route/distance/duration between itinerary stops.
- Restrict fields, page sizes and call counts.
- Add configurable per-request provider budgets/limits and timeouts.
- Keep Google API keys server-side for web-service calls. Browser map keys, if used later, must be separately restricted by referrer and API.
- Do not make a paid call until the human has configured billing and approved the test.

## Internal contracts

Create Zod-validated normalized types such as:
- `FlightSearchRequest`, `FlightOffer`, `FlightSegment`
- `WeatherRequest`, `WeatherForecast`
- `PlaceSearchRequest`, `Place`
- `RouteRequest`, `RouteResult`
- `ProviderSource` with provider name, retrievedAt, environment and attribution where applicable.

Do not leak raw provider response shapes into the LLM prompt or frontend. Preserve useful provider identifiers and source URLs where permitted.

## Reliability and tests

- Unit-test mapping from provider payloads to normalized types using saved, sanitized fixtures.
- Mock HTTP in tests; do not require live credentials for normal CI.
- Add bounded timeout, retry only safe transient failures, exponential backoff with jitter and `Retry-After` support where appropriate.
- Do not blindly retry non-idempotent operations.
- Normalize provider errors without logging tokens or full sensitive payloads.
- Add opt-in live smoke tests, disabled by default.

## Delegation

- Flights agent owns Amadeus adapter and tests.
- Weather agent owns Open-Meteo adapter and tests.
- Maps agent owns Google Places/Geocoding/Routes adapters and tests.
- QA/research agent checks official API contracts and tests edge cases.
- Supervisor defines shared normalized contracts before workers implement against them, integrates and runs all tests.

## Acceptance criteria

- [ ] Each provider is behind an interface/adapter.
- [ ] Provider response validation and normalized types exist.
- [ ] Unit tests pass without API keys.
- [ ] Opt-in live tests are documented and disabled by default.
- [ ] Flight test/production mode is explicit.
- [ ] Forecast horizon limitations are surfaced honestly.
- [ ] Maps field masks and call limits are implemented.
- [ ] Timeout, rate-limit and provider-error behavior is tested.
- [ ] Secrets are never returned to clients or logged.
- [ ] Human approves before M3.

## Out of scope

No LLM tool loop, UI, itinerary generation or booking.
