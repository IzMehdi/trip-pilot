# M0 — Project initialization and technical validation

## Role

Act as TripPilot's Project Manager/Supervisor. Follow `SUPERVISOR_PLAYBOOK.md`. Delegate independent research and repository setup tasks to Pi coding-agent instances. Do not implement later milestones.

## Objective

Create a clean, reproducible GitHub project foundation and validate that the chosen external providers can support the intended product. Resolve architectural risks before substantial implementation.

## Required work

### 1. Repository and Git foundation
- Verify the current repository root, Git remote and default branch.
- If no repository exists, ask the human to create an empty GitHub repository; do not fabricate a remote or assume an old repository exists.
- Establish `main` and `develop` branches, with `main` protected through GitHub settings where available.
- Add `.gitignore`, `.editorconfig`, `README.md`, `LICENSE` placeholder decision (ask owner before selecting), `CONTRIBUTING.md`, and `docs/`.
- Add this milestone pack to `docs/milestones/`.
- Add a basic CI workflow that runs on pull requests. It may initially validate repository metadata and later be extended.
- Do not commit secrets or generated credentials.

### 2. Technical architecture decision
Create `docs/architecture/overview.md` describing:
- React + Vite frontend.
- TypeScript + Node.js 22+ backend using Fastify.
- Zod validation at trust boundaries.
- Provider adapters for flights, weather, geocoding, places and routing.
- NVIDIA LLM client behind an interface.
- Tool registry/executor controlled by backend code.
- SSE stream endpoint and event contract (implemented in M4).
- PostgreSQL as a later persistence option; do not add a database in M0 unless a verified dependency requires it.
- Docker Compose deployment (M8).
- Data flow, trust boundaries, error handling and secret management.

### 3. Provider feasibility research
Delegate one research task per provider. Use official provider documentation only for capability and pricing claims.

**NVIDIA**
- Identify a currently accessible NVIDIA-hosted model endpoint.
- Verify exact model ID, base URL, authentication format and SDK compatibility.
- Verify streaming and tool/function-calling support with a minimal disposable proof of concept.
- Record rate limits, context constraints and any account restrictions.
- Do not assume every NVIDIA model endpoint supports the same capabilities.
- Treat free developer access as prototyping/development access, not unlimited production use.

**Amadeus**
- Verify account registration and current Flight Offers Search API access.
- Document test versus production environment differences, quotas, required fields and known coverage exclusions.
- Build a minimal non-committing test request only if credentials are supplied.
- Do not claim production live pricing when using the test environment.

**Open-Meteo**
- Verify forecast and geocoding endpoints, forecast horizon, variables, attribution and fair-use limits.
- No key should be required for the free non-commercial endpoint.

**Google Maps Platform**
- Verify Places API (New), Geocoding and Routes API requirements.
- Document billing requirement, current SKU pricing/free caps, field masks, API-key restrictions and budget alerts.
- Ask the human before enabling billing or making paid calls.

### 4. Project conventions
Create `docs/architecture/decisions.md` with dated decisions and alternatives. Add `docs/development.md` with local setup and environment-variable naming conventions (names only, no values).

## Delegation plan

- Research agent: NVIDIA endpoint capability proof and official references.
- Research agent: Amadeus test/production and Flight Offers Search constraints.
- Research agent: Open-Meteo and Google Maps current API policies/pricing.
- Repository agent: GitHub structure, CI, editor configuration and docs scaffolding.
- Supervisor: architecture synthesis, verify claims, integrate and review.

Only run provider research tasks in parallel; do not let research agents modify the same architecture document. Give each a separate report file or ask them to return findings.

## Acceptance criteria

- [ ] Correct GitHub remote and branches verified.
- [ ] No untracked secret files or committed credentials.
- [ ] Architecture overview and decisions documented.
- [ ] Provider research includes official links, date checked and limitations.
- [ ] NVIDIA proof of concept demonstrates actual response; tool call and streaming separately tested if supported.
- [ ] Amadeus test/production distinction documented.
- [ ] Maps billing exposure documented and human approval obtained before any paid test.
- [ ] CI workflow exists and passes.
- [ ] Supervisor provides a milestone report and requests human approval before M1.

## Out of scope

No complete backend, UI, production integrations, database schema, booking flow or deployment.
