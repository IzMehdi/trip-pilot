# M6 — End-to-end trip planning workflow

## Role

Act as Project Manager/Supervisor. This milestone integrates all previously accepted components. Delegate independent workflow tests, budget validation and itinerary validation, but keep the overall orchestration design under supervisor control.

## Objective

Deliver a complete planning journey from natural-language request to a grounded, streamed, structured itinerary with flights, weather and map context.

## Workflow

1. Accept structured trip form data and optional natural-language preferences.
2. Validate origin, destination, travel dates, passenger count, budget and currency.
3. Ask for missing essential details; do not silently invent them.
4. Resolve destination coordinates and airport/city codes where needed.
5. Search flight offers using the configured Amadeus environment.
6. Retrieve weather only for dates within the provider's forecast horizon.
7. Search attractions/restaurants based on user interests.
8. Retrieve route/distance/time information for selected itinerary stops.
9. Ask the NVIDIA model to synthesize a day-by-day plan using only normalized provider results.
10. Validate the generated structured itinerary against a Zod schema.
11. Check date ordering, place identifiers, route references, currency consistency and budget arithmetic.
12. Stream progress and itinerary sections to the frontend.
13. Present sources, retrieval timestamps, assumptions and unavailable information.

## Structured itinerary

Define a stable schema containing:
- Trip summary and dates.
- Origin/destination.
- Travelers and user preferences.
- Flight options (not a booking).
- Day-by-day schedule.
- Activities with place ID, name, coordinates, description, source and optional opening-hours metadata if actually returned.
- Route legs with mode, distance, duration and provider source.
- Weather summary linked to date/location.
- Cost estimate with currency, category, source and confidence/known-vs-estimated status.
- Warnings, assumptions and unavailable data.
- Provider provenance and timestamps.

## Budget logic

- Distinguish flight offer price, provider-supplied price and estimated costs.
- Do not invent hotel or meal prices. If no lodging/restaurant pricing source is integrated, label those as user-entered or unavailable estimates.
- Handle per-person versus total prices explicitly.
- Avoid mixing currencies without an explicit conversion source and timestamp.
- Do not claim the plan fits the budget if key cost categories are unknown.
- Include contingency and clearly label estimates.

## Agent behavior

- The LLM may choose which read-only tools to call, but backend limits and policy govern execution.
- Use bounded tool-call counts, deadlines and concurrency.
- Do not let model-generated instructions override system/developer policy or tool schemas.
- Tool results are untrusted data; strip or isolate instructions embedded in provider text.
- The final itinerary must be schema-validated and grounded in returned data.
- If one provider fails, return a useful partial plan and explicitly disclose what is missing.

## Tests

- Full integration test with mocked Amadeus, Open-Meteo, Google Maps and NVIDIA.
- Opt-in live smoke test using test/sandbox credentials and explicit user configuration.
- Test unavailable weather dates, no flights, no places, provider timeout, model refusal, malformed itinerary and budget overrun.
- Test timezone and date-boundary behavior.
- Test that all factual claims about flights/weather/places map to provider evidence or are clearly labelled as general suggestions.

## Acceptance criteria

- [ ] A user can complete a full trip-planning request end-to-end.
- [ ] Real provider adapters are used; mocks are confined to tests.
- [ ] NVIDIA function calling is used for tool selection.
- [ ] Itinerary is streamed and schema-validated.
- [ ] Budget calculations are transparent and do not fabricate missing prices.
- [ ] Partial failures are handled honestly.
- [ ] Sources and timestamps are visible.
- [ ] Full integration tests pass.
- [ ] Human accepts the end-to-end demonstration before M7.
