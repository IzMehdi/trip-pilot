# M7 — Testing, security, reliability and observability

## Role

Act as Project Manager/Supervisor. Delegate independent security review, reliability testing and test-coverage work. Treat findings seriously; do not suppress or waive high-severity issues without human approval.

## Objective

Harden TripPilot for reliable local/staging use. This milestone does not authorize public production deployment.

## Security review

- Audit secret handling, environment configuration and log redaction.
- Confirm provider keys exist only on the backend.
- Validate CORS, rate limits, request sizes and timeouts.
- Protect against prompt injection in user input and untrusted provider text.
- Ensure tool registry allowlists tool names and validates arguments.
- Prevent SSRF: do not let the model or user provide arbitrary URLs for backend fetching.
- Prevent path traversal and unsafe file operations.
- Review dependency vulnerabilities and license obligations.
- Ensure no Docker socket or unnecessary host mounts are exposed to runtime containers.
- Check that errors do not reveal stack traces, tokens or internal paths to clients.
- Review privacy: minimize stored user travel data and document retention/deletion behavior.

## Reliability

- Add bounded retries with backoff for safe transient provider errors.
- Add request deadlines and cancellation propagation.
- Add per-user/IP and per-trip quotas as appropriate.
- Add circuit-breaker or provider-health behavior only if justified by observed needs.
- Ensure partial provider outages produce partial results rather than hangs.
- Avoid duplicate work when clients disconnect or retry.
- Add graceful shutdown and cleanup of active streams.
- Add cache only for data where freshness and provider terms allow it; include TTL and provenance.

## Observability

- Structured logs with request/trip correlation IDs.
- Metrics for request duration, provider latency/error rates, LLM latency, tool counts, stream duration and cancellations.
- Do not log full prompts, personal details, API keys or raw provider responses by default.
- Add a safe diagnostic endpoint or documented operational checks; do not expose sensitive internals publicly.

## Testing

- Unit, integration and browser smoke tests.
- Negative/adversarial tests for malformed tool arguments, prompt injection, huge inputs, repeated tool calls and cancellation.
- Load test a small controlled workload with mocked providers; do not stress public APIs.
- Validate accessibility and basic performance.
- Add dependency and static-analysis checks to CI.
- Define a release checklist and known limitations.

## Delegation

- Security reviewer: read-only threat model and code review, then bounded fixes if approved.
- QA agent: integration, edge-case and regression tests.
- Reliability agent: timeouts, cancellation, rate limits and failure handling.
- Supervisor: prioritize findings, coordinate fixes and verify each resolution.

## Acceptance criteria

- [ ] No known unresolved critical/high security issue.
- [ ] Secret and PII redaction tests pass.
- [ ] Tool and provider calls are bounded.
- [ ] Cancellation and shutdown are reliable.
- [ ] CI runs tests, typecheck, lint and security checks.
- [ ] Provider failures and partial results are tested.
- [ ] Logs and metrics do not expose secrets or unnecessary personal data.
- [ ] Threat model and operational runbook are documented.
- [ ] Human approves deployment preparation before M8.
