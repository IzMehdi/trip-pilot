# M1 — Backend foundation

## Role

Act as Project Manager/Supervisor. Read `SUPERVISOR_PLAYBOOK.md` and the accepted M0 architecture. Delegate bounded implementation tasks to isolated Pi worktrees.

## Objective

Build a maintainable Fastify backend skeleton with reliable configuration, validation, errors, logging and tests. No LLM orchestration or live provider integrations yet.

## Required implementation

- Initialize a TypeScript Node.js 22+ backend workspace using the package manager selected in M0.
- Configure strict TypeScript, linting, formatting, scripts and test runner (Vitest recommended).
- Implement Fastify server startup and graceful shutdown.
- Add `GET /health` and `GET /ready` endpoints. Readiness should reflect application initialization, not pretend external providers are healthy.
- Centralize environment parsing and validation with Zod. Fail fast with safe messages if required configuration is missing.
- Add structured request logging with correlation/request IDs; redact authorization headers and secret-like fields.
- Add consistent error response shape with stable error codes, safe public messages and internal diagnostic logging.
- Add request body/query validation patterns and response schemas where practical.
- Add CORS configuration with explicit allowed origins; no wildcard production configuration.
- Add rate limiting for public endpoints, with configurable limits.
- Add a small `/api/v1` route structure and dependency injection pattern for services.
- Add unit tests for config parsing, error serialization, validation and health endpoints.
- Add `.env.example` containing variable names and safe placeholders only.
- Ensure `.env` and local secret files are ignored.

## Suggested module boundaries

```text
apps/
  api/
    src/
      app.ts

      config/
      plugins/
      routes/
      errors/
      logging/
      modules/
    test/
packages/
  shared/
    src/
```

Adapt to M0's approved monorepo layout; do not force this exact tree if the accepted architecture differs.

## Delegation

- Backend agent: server, route registration, lifecycle and health endpoints.
- Platform agent: TypeScript/tooling, lint, test and CI integration.
- QA agent: tests for error handling, config and validation.
- Supervisor: define shared interfaces first, avoid overlapping edits, integrate and review.

## Acceptance criteria

- [ ] Clean install from lockfile succeeds.
- [ ] TypeScript typecheck passes.
- [ ] Lint and format checks pass.
- [ ] Unit tests pass.
- [ ] Health and readiness endpoints return documented responses.
- [ ] Invalid configuration fails safely.
- [ ] Secrets are redacted from logs and absent from Git.
- [ ] Graceful shutdown works.
- [ ] CI runs the checks on pull requests.
- [ ] Human approves milestone report before M2.

## Out of scope

No external provider calls, LLM, streaming itinerary, frontend or database-dependent product features.
