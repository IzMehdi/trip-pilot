# M8 — Docker deployment and final documentation

## Role

Act as Project Manager/Supervisor. Delegate containerization, deployment documentation and final verification to isolated workers. Ask the human before publishing an image, provisioning paid infrastructure or deploying to a public URL.

## Objective

Package TripPilot for reproducible local/staging deployment and deliver complete developer/operator documentation.

## Docker requirements

- Add production-oriented Dockerfiles for frontend and backend.
- Use multi-stage builds and minimal runtime images.
- Run application processes as non-root users.
- Pin base image versions and lock dependencies.
- Add health checks where meaningful.
- Use Docker Compose for local application orchestration.
- Keep secrets out of image layers, build args, source control and container logs.
- Use an `.env.example` with placeholders only.
- Do not mount the Docker socket into application containers.
- Do not use privileged containers.
- Restrict container capabilities and writable filesystems where practical.
- Document network boundaries and persistent volumes.
- Do not assume Docker Compose is a production orchestrator.

## Configuration and deployment

Document:
- Required and optional environment variables.
- How to obtain NVIDIA, Amadeus and Google Maps credentials.
- Which provider modes are test versus production.
- How to configure billing limits and API-key restrictions.
- How to run migrations if persistence was introduced.
- How to run local development, tests and Docker Compose.
- How to update, back up and restore persistent data if applicable.
- How to rotate credentials.
- How to diagnose provider failures and stream errors.

## Final product verification

- Start the application from a clean checkout using documented steps.
- Run CI checks and all tests.
- Run a controlled end-to-end demo with provider environments clearly identified.
- Confirm no secrets appear in Git history, image layers or logs.
- Confirm API usage/cost controls are documented.
- Capture known limitations, especially Amadeus coverage, NVIDIA model access and map-provider billing.
- Add architecture diagram and final API documentation.
- Prepare a release checklist and version tag proposal; do not create a public release without human approval.

## Delegation

- DevOps agent: Dockerfiles, Compose, health checks and container hardening.
- Documentation agent: setup, provider credentials, API and operations documentation.
- QA agent: clean-checkout and deployment smoke tests.
- Security reviewer: final image/configuration audit.
- Supervisor: integrate, verify and prepare final report.

## Acceptance criteria

- [ ] Clean checkout can be built and run using documented commands.
- [ ] Docker containers run non-root and do not require privileged mode.
- [ ] Secrets are injected at runtime and never baked into images.
- [ ] Health checks and shutdown behavior work.
- [ ] CI and all tests pass.
- [ ] Provider modes, limitations and costs are documented.
- [ ] End-to-end demo works with clearly labelled provider environments.
- [ ] Final architecture, setup and operations docs are complete.
- [ ] Human approves any public deployment or release.
